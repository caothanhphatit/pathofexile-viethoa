# Pilot: Path of Building as the data source for skill gems and unique items

Question: can PoB's data replace the poe2db crawl as the source of truth for
`public/data/skill-gems-data.js` and the unique rows of `public/data/items-data.js`?

This is a feasibility pilot. Nothing under `public/data/` was changed and the site was not switched over.

Every number below comes from `node scripts/pob-data/compare.mjs`, which writes
[`docs/pob-data-pilot-numbers.md`](pob-data-pilot-numbers.md) (all tables, 10 examples per
field and kind, full leftover lists). Sums of those numbers are marked as sums.

## Verdict

| | verdict | short reason |
|---|---|---|
| Skill gems | **Yes, with gaps** | Structure and numbers match well; 92.7% of the site's tooltip stat lines are reproduced character for character. But this PoB checkout lacks 78 gems the site has, and several things poe2db shows are not in PoB at all. |
| Unique items | **Yes, with gaps** | 439 of 468 site uniques exist in PoB; mods are identical or equivalent for 371 of 439 (sum). PoB adds flavour text, league, drop source and patch variants. Requirements are weaker than the site's, and relics/tablets are missing. |

One premise did not hold: **this PoB checkout is older than the crawl.** PoB commit `bb52d6b` is
dated 2026-10-01; the site data was generated 2026-11-07 and the game extract 2026-11-05. Where the
two disagree, "PoB is newer" cannot be assumed here; the game extract was used as referee where it
has the field. Whether a newer PoB commit closes the gaps was not checked (the checkout is read-only
for this pilot).

## What was built

| file | purpose |
|---|---|
| `scripts/pob-data/dump.lua` | Runs inside PoB's own LuaJIT (HeadlessWrapper), so PoB's loader reads `Gems.lua`, `Skills/*.lua`, `Uniques/*.lua`, `Bases/*.lua`, `FlavourText.lua`, and PoB's own `StatDescriber` renders every stat set at level 1, at the gem's natural max level and as a range. |
| `scripts/pob-data/dump.mjs` | Starts the dump (`<pob-core>/runtime/pob-luajit-bin/pob-luajit.exe`, cwd `<pob-core>/src`), rewrites the JSON with sorted keys. Three runs gave byte-identical files. |
| `scripts/pob-data/generate-gems.mjs`, `generate-uniques.mjs` | Pure functions: PoB dump to records in the site's shape. |
| `scripts/pob-data/generate.mjs` | CLI: writes `data/pob-extract/skill-gems.generated.json` and `uniques.generated.json`. |
| `scripts/pob-data/compare.mjs` | Pairs records, classifies every field, writes `data/pob-extract/compare.json` and `docs/pob-data-pilot-numbers.md`. |
| `tests/pob-data.test.mjs` | 15 tests (one runs the real dump when a PoB checkout is present, otherwise it is skipped). |

```
node scripts/pob-data/generate.mjs --dump    # PoB -> data/pob-extract/*.json
node scripts/pob-data/compare.mjs            # -> docs/pob-data-pilot-numbers.md
```

`data/` is git-ignored in this repo, so the JSON under `data/pob-extract/` is not committed; it is
regenerated by the two commands above.

**Full regeneration time** (three runs on this machine): dump 2.6 to 4.8 s, generate about 0.1 s,
compare about 0.3 s. Under 6 seconds end to end, no network.

Where PoB and poe2db differ only in presentation, the generator follows the site so lines can be
compared one to one: em-dash ranges, ranges inside stat text running low to high, level 1 to max
merged into one line, undescribed stats listed as `stat id [value]`, `Cooldown Time: 4.00 s`,
no `Cast Time: Instant` in the header. These conventions are listed at the top of `generate-gems.mjs`.

### Gem text (the hard part)

Site stat lines fall into three kinds: described lines (real tooltip text), cost/timing lines that
poe2db prints inside secondary sections, and raw lines (stats without description, e.g. `base is projectile [1]`).

| measure | count | share |
|---|---:|---:|
| matched gems | 960 | |
| gems whose sections are identical (titles, every line, order) | 691 | 72.0% |
| gems where every described site line is produced character for character | 801 | 83.4% |
| gems where every site line of any kind is produced exactly | 761 | 79.3% |
| described site lines | 3,876 | |
| ...produced exactly | 3,593 | 92.7% |
| ...not produced | 283 | 7.3% |
| cost/timing lines inside sections | 423 | |
| ...produced exactly | 320 | 75.7% |
| raw stat lines | 5,202 | |
| ...produced exactly | 5,052 | 97.1% |
| described lines PoB produces that the site lacks | 187 of 3,763 | 5.0% |

**So: 83.4% of gems can be rendered fully as far as real tooltip text goes, 72.0% are identical
including poe2db's raw lines and section layout.** By type (all described lines exact): supports
518 of 566 (91.5%), Buff 79 of 90, Attack 110 of 155 (71.0%), Spell 64 of 99 (64.6%), Minion 17 of 29,
Warcry 5 of 7, Totem 2 of 4, Mark 0 of 4.

What the 283 missing lines are (examples in the numbers file; the split was read from the examples, not counted):

- **Values the game client derives and PoB does not store.** `Explosion and Chilled Ground radius are 4.8 metres`,
  `Chilled Ground duration is 8 seconds` on secondary stat sets; PoB shows the underlying raw stat
  (`active skill base area of effect radius [48]`) instead.
- **Minion skills.** Skeletal Sniper has 5 sections on the site (Command, Impact, Poison Cloud...);
  PoB's gem only has `Minion Info` with no described line. The minion's own skills live in `Minions.lua`, which this pilot did not render.
- **Hidden stat sets.** The site has 17 sections titled `Hidden` (e.g. Ice Nova cast on a Frostbolt);
  PoB's `additionalStatSet` entries are not part of the gem's rendered effects.
- **Rounding.** `Deals (6.5—221.4) Cold damage per second` (site) vs `(6.4—221.3)` (PoB); per-minute stats
  are floored by PoB. Not determined which the game shows.
- **Grammar by value.** `Limit 1 Volcanoes`, `Applies a socketed Mark to 1 Enemies` on the site;
  PoB picks the singular form (`Limit 1 Volcano`). PoB reads better; the site line is poe2db's.
- **Real data differences**, e.g. Apocalypse final strike `Deals (3—169) to (20—958)` (site) vs
  `(4—228) to (27—1293)` (PoB). With PoB five weeks older than the crawl, the site is the likelier current value; not verified.
- `Fires +1 Projectiles` on concoction skills: on the site only.

## What a switch-over would need

1. **A current PoB checkout**, and a check of how many of the 66 missing gems it then covers. Regeneration is cheap (under 6 s), so it can run on every PoB update.
2. **Keep poe2db (or the game extract) as a fallback** for what PoB lacks: the missing gems, relics, tablets, Projectile Speed and Use Time, granted-skill levels, icons for supports and uniques. A merge step that takes PoB where it has data and the current source elsewhere, per field, is the realistic shape; a full replacement is not possible today.
3. **Decide the conventions** the pilot only mirrored: raw stat lines (PoB could simply drop them, they are poe2db debug output), `Hidden` sections, how option variants of uniques are shown, `Ward` vs `Runic Ward`.
4. **Keys**: site slugs are poe2db page names (`Herald_of_Ash__3`, `Arbiter's_Reach`). 36 gem slugs (16 + 20, sum) and 1 unique slug would change with a name-derived slug, so URLs need a slug map or redirects. Join on `official_id` for gems (956 of 960 identical).
5. **Translations**: carry over `vi` text by English line, list what is new, and run the translation step on the remainder.
6. **Use the game extract for** gem `color`, unique requirements, and as the referee in an automated check (the compare script already does this for tier, tags, colour and summary).
7. **Render minion skills and additional stat sets** from PoB if the site should keep those sections (not done in the pilot).
8. Wire `generate.mjs` into the export scripts and add the record fields the site needs but the pilot left out (`status`, hashes, `updated_at`, `item_category`, `build_slot_categories`).

## Limits of this pilot

- One PoB commit (`bb52d6b`), one site snapshot (2026-11-07), one game extract (2026-11-05).
- "Which side is right" was only decided where the game extract has the field (gem tier, tags, colour, description, base item requirements). Everything else is reported as a difference without a verdict.
- Gem text was compared as rendered ranges for level 1 to the natural max level, not level by level.
- The unique comparison shows PoB's `Current` variant only; older variants were used only to recognise stale site rows (2 found).
